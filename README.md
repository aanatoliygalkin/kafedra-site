# Сайт кафедры информационных систем в экономике и управлении

Веб-сайт кафедры АНО ВО «РосНОУ»: новости, преподаватели, дисциплины, документы,
контактная информация и панель управления содержимым.

**Демонстрация:** <https://aanatoliygalkin.github.io/kafedra-site/>
(демо-режим: данные хранятся в браузере, вход в панель — `admin@iseu.local` / `admin123`)

## Технологии

| Что | Версия |
| --- | --- |
| Next.js (App Router, статический экспорт) | 14.2 |
| React | 18.3 |
| TypeScript | 5.6 |
| Вёрстка | обычный CSS (`src/app/globals.css`), без UI-фреймворков |
| База данных (опционально) | Supabase (PostgreSQL + Auth + Storage) |

Сборка статическая (`output: 'export'`), поэтому сайт можно разместить на любом
хостинге статики: GitHub Pages, Netlify, обычный веб-сервер.

## Быстрый старт

Нужен Node.js 18.17 или новее (проверено на 20 и 22).

```powershell
cd kafedra-site
npm install
npm run dev       # разработка: http://localhost:3000
npm run build     # сборка статических файлов в каталог out/
npm run preview   # просмотр уже собранного сайта
```

## Два режима работы

**Демо-режим (по умолчанию, без настроек).** Если переменные окружения не заданы,
сайт берёт данные из `src/lib/demo-data.ts`, а панель управления сохраняет изменения
в `localStorage` браузера. Этого достаточно для показа на защите: сайт полноценно
работает без сервера и без интернета.

Вход в панель управления: **admin@iseu.local / admin123**
(адрес: `/login`, после входа — `/admin`).

**Режим с базой данных (Supabase).**

1. Создайте проект на [supabase.com](https://supabase.com).
2. В SQL Editor по очереди выполните файлы из каталога `supabase/`:
   `001_init.sql` → `002_rls.sql` → `003_storage.sql` → `004_seed.sql`.
3. Скопируйте `.env.example` в `.env.local` и укажите адрес проекта и `anon`-ключ:
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
   ```
4. Перезапустите `npm run dev`.

`service_role`-ключ в проект добавлять нельзя: он попадает в клиентскую сборку.

## Структура проекта

```
kafedra-site/
├─ src/app/                 страницы (App Router)
│  ├─ page.tsx              главная
│  ├─ news/                 список новостей и страница новости
│  ├─ teachers/             состав кафедры
│  ├─ courses/              дисциплины
│  ├─ documents/            архив документов
│  ├─ info/                 «О кафедре», «Поступающим», «Контакты»
│  ├─ login/                вход
│  └─ admin/                панель управления (новости, преподаватели,
│                           дисциплины, документы, текстовые страницы)
├─ src/components/          шапка, подвал, карточки, таблицы, скелетоны
├─ src/lib/                 доступ к данным, авторизация, типы, форматирование
├─ public/                  статические файлы: PDF-документы, robots.txt, .nojekyll
├─ supabase/                SQL-скрипты схемы, прав доступа и демо-данных
└─ .github/workflows/       автоматическая публикация на GitHub Pages
```

## Публикация на GitHub Pages

Сайт уже опубликован: репозиторий <https://github.com/aanatoliygalkin/kafedra-site>,
страница — <https://aanatoliygalkin.github.io/kafedra-site/>. Источник сборки в
настройках Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Обновление сайта — обычный push в ветку `main`:

```powershell
git add .
git commit -m "Правка текста страницы"
git push
```

Через 1–2 минуты сборка во вкладке **Actions** завершится и сайт обновится.
При каждом push workflow собирает проект (`npm ci` → `npm run build`) и публикует
каталог `out`.

Подкаталог `/имя-репозитория/` подставляется автоматически: workflow передаёт его
в сборку через `NEXT_PUBLIC_BASE_PATH`, поэтому переименование репозитория ничего
не ломает. Файл `public/.nojekyll` уже добавлен — без него GitHub Pages скрывает
каталог `_next` со стилями и скриптами.

Если понадобится поднять сайт в новом репозитории: создайте на GitHub пустой
репозиторий, выполните `git remote set-url origin <адрес>`, `git push -u origin main`
и выберите источник «GitHub Actions» в настройках Pages.

`package-lock.json` закоммичен, workflow использует `npm ci` — сборка
воспроизводимая.

## Проверка перед защитой

Достаточно открыть сайт и пройти по разделам: главная → новости → страница
новости → преподаватели → дисциплины → документы (скачивание PDF) → о кафедре →
вход → панель управления → создание новости → она появилась на сайте.
